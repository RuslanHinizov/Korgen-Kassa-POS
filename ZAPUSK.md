## 0. Что нужно установить

| Программа | Зачем | Где взять |
|---|---|---|
| **Git** | скачать проект | https://git-scm.com |
| **Docker Desktop** (Windows/macOS) или Docker Engine (Linux) | запуск базы данных и приложения | https://www.docker.com/products/docker-desktop |
| **Node.js 22** | служебные скрипты, сборка программы кассира, режим разработки | https://nodejs.org |

Для запуска из раздела 1 достаточно **Git и Docker**. Node.js нужен для разделов 2, 3 и 4.

Проверьте, что всё установлено:

```bash
git --version
docker --version
docker compose version
node --version        # нужен v22 или новее
```

## 1. Запуск на новом компьютере (Docker)

Подходит, чтобы быстро поднять систему на одном компьютере: попробовать, показать, поработать локально.

### Шаг 1. Скачать проект

```bash
git clone https://github.com/turdalievzhandos-wq/Korgen-Kassa-POS-V1.git
cd Korgen-Kassa-POS-V1
```

(Репозиторий закрытый: GitHub попросит войти в аккаунт, у которого есть доступ.)

### Шаг 2. Создать файл настроек `.env`

Windows (PowerShell):
```powershell
Copy-Item .env.example .env
```
Linux / macOS:
```bash
cp .env.example .env
```

Откройте `.env` в любом редакторе и замените значение `BETTER_AUTH_SECRET` на длинный случайный секрет (минимум 32 символа).
Получить его можно командой:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64'))"
```

Остальные строки для запуска на одном компьютере менять не нужно (адрес `http://localhost:3000`).

### Шаг 3. Запустить

```bash
docker compose up -d --build
```

Первая сборка занимает несколько минут. Дождитесь, пока команда завершится.

### Шаг 4. Создать таблицы базы данных

```bash
docker compose exec web npx prisma migrate deploy
```

### Шаг 5. Открыть систему

Откройте в браузере **http://localhost:3000**. При первом входе откроется **мастер первоначальной настройки**: укажите название
магазина и создайте учётную запись администратора. После этого войдите по номеру телефона и паролю.

### Остановка и повторный запуск

```bash
docker compose stop        # остановить (данные сохраняются)
docker compose start       # запустить снова
docker compose down        # удалить контейнеры (данные остаются в томах)
docker compose down -v     # удалить ВСЁ, включая базу данных (необратимо!)
```

## 2. Режим разработки (без Docker для приложения)

База данных всё равно удобнее держать в Docker.

```bash
git clone https://github.com/turdalievzhandos-wq/Korgen-Kassa-POS-V1.git
cd Korgen-Kassa-POS-V1

# только база данных
docker compose up -d postgres

# настройки (см. шаг 2 раздела 1)
cp .env.example .env            # Windows: Copy-Item .env.example .env

npm install -g pnpm             # один раз
pnpm install
npx prisma migrate deploy       # создать таблицы
pnpm dev                        # http://localhost:3000
```

Полезные команды:

| Команда | Что делает |
|---|---|
| `pnpm dev` | запуск с автоматическим обновлением страницы |
| `npx vitest run` | модульные тесты |
| `npx tsc --noEmit` | проверка типов |
| `npx eslint` | проверка стиля кода |
| `pnpm db:studio` | просмотр базы данных в браузере |

## 3. Боевой сервер (VPS)

Для настоящего магазина система ставится на сервер с Linux (подойдёт любой VPS: Ubuntu 22.04 и новее, от 2 ГБ памяти, от 20 ГБ диска).

**Что нужно заранее:**
- сервер с установленным Docker;
- домен, у которого **A-запись указывает на IP сервера** (например, `pos.вашдомен.kz`);
- открытые порты **80** и **443**.

### Первый запуск

На сервере:

```bash
git clone https://github.com/turdalievzhandos-wq/Korgen-Kassa-POS-V1.git /opt/korgen
cd /opt/korgen

# создаёт .env.production со случайными секретами
node scripts/gen-secrets.mjs pos.вашдомен.kz

# запускает HTTPS + приложение + базу + ночные резервные копии
docker compose --env-file .env.production -f docker-compose.prod.yml up -d --build
```

- Сертификат HTTPS Caddy получает и продлевает сам.
- База данных не доступна снаружи, наружу открыты только порты 80 и 443.
- **Файл `.env.production` обязательно скопируйте в надёжное место вне сервера** (менеджер паролей). Без пароля базы данных
  восстановить систему на новом сервере будет невозможно.

### Владелец платформы (первый вход)

```bash
docker compose --env-file .env.production -f docker-compose.prod.yml exec web \
  node scripts/create-superadmin.mjs "+7 (777) 123-45-67" "Владелец"
```

Скрипт один раз напечатает пароль. Войдите на `https://pos.вашдомен.kz/login`, откройте раздел `/superadmin` и **создайте магазин**.
Дальше работайте уже внутри магазина: добавьте сотрудников, товары, кассы.

### Обновление

Безопасное обновление с резервной копией и возможностью отката:

```bash
# 1. На своём компьютере упакуйте код (из папки проекта):
git archive --format=tar.gz -o korgen-src.tar.gz HEAD
scp korgen-src.tar.gz root@IP-СЕРВЕРА:/root/

# 2. На сервере:
cd /opt/korgen
sh deploy/update.sh /root/korgen-src.tar.gz
```

Скрипт сам сделает резервную копию базы, соберёт новую версию, применит миграции и проверит, что приложение отвечает.
Если что-то пошло не так — вернуться на предыдущую версию:

```bash
sh deploy/rollback.sh
```

### Резервные копии и обслуживание

- Копии базы делаются **каждую ночь** автоматически (последние 14 дневных и 8 недельных).
- Резервные копии на том же сервере пропадают вместе с сервером — **периодически скачивайте их на другой компьютер**.
- `sh deploy/restore.sh <файл>` — проверить копию или восстановить из неё.
- `sh deploy/cleanup.sh` — освободить место на диске (старые образы Docker, старые копии и установщики).
- `docs/server-reset.md` — полная очистка сервера и начало с нуля.

Подробно: [docs/production.md](docs/production.md).

## 4. Программа кассира (Windows)

Устанавливается на кассовый компьютер (моноблок). Нужен Windows 10 или новее.

### 4.1. Установка

1. Скачайте установщик `Korgen Kassa Setup X.Y.Z.exe` (последний выложен на вашем сервере в папке обновлений:
   `https://pos.вашдомен.kz/till-updates/`) и запустите его. Программа установится для текущего пользователя и откроется.
2. Позже новые версии программа найдёт и поставит **сама**.

### 4.2. Подключение кассы к магазину

1. В веб-кабинете откройте **Управление → Кассы** и создайте кассу (если её ещё нет).
2. В блоке «Код активации кассы» выберите кассу и получите **8-значный код** (действует 24 часа, вводится один раз).
3. В программе на кассе введите код и нажмите «Активировать». Товары и настройки магазина загрузятся сами (нужен интернет, для
   большого каталога потребуется несколько минут).
4. Добавьте кассиров: **Управление → Пользователи**, укажите **PIN-код**. Затем кассир выбирает своё имя на экране «Вход в кассу» и
   вводит PIN.

Если интернета на кассе нет совсем, данные магазина можно загрузить файлом («Загрузить пакет магазина») — файл скачивается в кабинете
в разделе «Пакет для офлайн-кассы».

### 4.3. Если нужно привязать кассу заново или закрыть программу

- На экране ввода кода и на экране «Вход в кассу» справа вверху есть кнопка **«Выйти из программы»**.
- На экране «Вход в кассу» также есть **«Сменить привязку кассы (новый код активации)»** — касса вернётся к вводу кода. Если на
  кассе остались не отправленные продажи, сначала подключите интернет и дождитесь отправки.

### 4.4. Принтер чеков

Подключите термопринтер (80 мм, ESC/POS, например Xprinter) по USB, установите его драйвер Windows. Программа сама найдёт принтер
и будет печатать чеки без диалогов; индикатор «ПРИНТЕР» вверху экрана зелёный, когда принтер готов. Если на компьютере несколько
принтеров, выберите нужный в файле `%APPDATA%\Korgen Kassa\config.json`:

```json
{ "printer": "название принтера" }
```

### 4.5. Размер интерфейса

Если кнопки слишком большие или маленькие: **ДОП. ФУНКЦИИ → РАЗМЕР ЭКРАНА → «−» / «+»**. Настройка запоминается на этом компьютере.

### 4.6. Сборка установщика самостоятельно (для разработчиков)

Нужны Node.js 22 и работающее приложение (раздел 1) — программа берёт экраны кассы из запущенной сборки.

```bash
cd till-app
npm install
node scripts/sync-web.mjs          # забирает экраны кассы из запущенного приложения
npm run dist                       # создаёт till-app/dist/Korgen Kassa Setup X.Y.Z.exe
```

Чтобы кассы обновились сами, увеличьте `version` в `till-app/package.json` и скопируйте **три файла** из `till-app/dist/`
(`latest.yml`, `Korgen Kassa Setup X.Y.Z.exe`, `…exe.blockmap`) на сервер в `/opt/korgen/till-updates/`. Файл `latest.yml`
копируйте последним. Подробно: [docs/till-updates.md](docs/till-updates.md).

## 5. Первая настройка магазина (чек-лист)

1. Войти как администратор магазина.
2. **Управление → Настройка чека**: название и текст внизу чека.
3. **Управление → Кассы**: проверить кассы и счета, получить коды активации.
4. **Управление → Пользователи**: добавить сотрудников и PIN-коды кассиров; задать **PIN менеджера** в настройках
   (нужен для долгов и быстрой приёмки).
5. **Товары**: загрузить каталог (импорт Excel) или добавить вручную; указать цены и остатки.
6. **Контрагенты → Поставщики**: добавить поставщиков, привязать их товары.
7. **Финансы**: проверить счета и начальные остатки.
8. Установить программу кассира (раздел 4), активировать, сделать пробную продажу, распечатать чек.

## 6. Частые проблемы

| Проблема | Что делать |
|---|---|
| `docker compose` не запускается | Откройте Docker Desktop и дождитесь, пока он полностью загрузится |
| Порт 3000 или 5432 занят | Остановите другую программу на этом порту или измените порт в `docker-compose.yml` |
| Сайт открывается, но пишет об ошибке базы | Выполните `docker compose exec web npx prisma migrate deploy` |
| Приложение не стартует и пишет про `BETTER_AUTH_SECRET` | Задайте в `.env` секрет не короче 32 символов |
| Забыли пароль владельца платформы | Создайте нового: `scripts/create-superadmin.mjs` (раздел 3) |
| Касса пишет «Касса отключена» | Магазин приостановлен или ключ кассы отозван. Свяжитесь с администратором; если нужно — привяжите кассу заново новым кодом |
| Код активации «неверный или уже использован» | Код одноразовый и живёт 24 часа: получите новый в Управление → Кассы |
| Чек не печатается | Проверьте, что принтер включён и виден в Windows; индикатор «ПРИНТЕР» в верхней панели должен быть зелёным |
| Нет места на сервере | `sh deploy/cleanup.sh` |
| Сервер не отвечает после обновления | `sh deploy/rollback.sh` и посмотрите `docker logs korgen-web-1 --tail 50` |
